Prima di cominciare

La pubblicazione si fa dal computer Linux dove tenete la cartella del progetto e dove avete l'accesso a GitHub (lo stesso usato per le versioni precedenti). I file della 2.3.0 sono sul PC Windows, nella cartella Download\ProfessoreDigitale-2.3.0.

FileServe per
professore-digitale-2.3.0-da-pubblicare.zip.00.parte
professore-digitale-2.3.0-da-pubblicare.zip.01.parte		Lo zip con tutto ciò che va sul sito, diviso in due parti (era troppo grande per essere inviato in un pezzo solo).
professore-digitale-2.3.0-sorgenti.tar.gzI nuovi sorgenti, con la cronologia git e il tag v2.3.0.

Legenda LINUX comandi da scrivere nel Terminale del PC Linux · WINDOWS comandi da scrivere nel Prompt dei comandi di Windows. Le righe che iniziano con # sono commenti: non vanno scritte.

1 · Portare i file sul PC Linux

Copiate con una chiavetta (o con la rete di casa) i tre file che servono — le due .parte, i sorgenti e SHA256SUMS — nella cartella Scaricati del PC Linux. Il resto dei comandi presuppone che siano lì.

Se preferite riunire lo zip già su Windows WINDOWS Aprite la cartella Download\ProfessoreDigitale-2.3.0, scrivete cmd nella barra degli indirizzi in alto e premete Invio, poi: 
copy /b professore-digitale-2.3.0-da-pubblicare.zip.00.parte + professore-digitale-2.3.0-da-pubblicare.zip.01.parte professore-digitale-2.3.0-da-pubblicare.zip
e copiate sul PC Linux lo zip intero al posto delle due parti (saltate allora il passo 2a).

2 · Riunire lo zip e controllare le impronte

LINUX Aprite il Terminale ed entrate nella cartella Scaricati:

cd ~/Scaricati

2a · Riunire le due parti

cat professore-digitale-2.3.0-da-pubblicare.zip.00.parte \
    professore-digitale-2.3.0-da-pubblicare.zip.01.parte \
    > professore-digitale-2.3.0-da-pubblicare.zip

2b · Controllare che i file siano integri

sha256sum -c SHA256SUMS --ignore-missing

Devono comparire OK accanto a professore-digitale-2.3.0-da-pubblicare.zip e a professore-digitale-2.3.0-sorgenti.tar.gz. Se compare un errore (per esempio FAILED o non corretto), ricopiate quel file: si è rovinato nel trasferimento.

Gli altri file elencati in SHA256SUMS che non avete copiato vengono ignorati: è normale.

3 · Sostituire la cartella dei sorgenti

I nuovi sorgenti contengono già tutto (anche la cronologia git e il tag della versione). La vecchia cartella si mette da parte, non si cancella:

# 1. si mette da parte la cartella della 2.2.0 (si potrà cancellare più avanti)
cd ~
mv professore-digitale professore-digitale-2.2.0-vecchia

# 2. si estraggono i nuovi sorgenti: si crea di nuovo la cartella professore-digitale
tar xzf ~/Scaricati/professore-digitale-2.3.0-sorgenti.tar.gz

# 3. si entra e si controlla la versione
cd ~/professore-digitale
cat VERSION                 # deve rispondere: 2.3.0
git log --oneline -1        # deve rispondere: ... Versione 2.3.0
Cartella in un altro posto?Se la vostra cartella del progetto non è ~/professore-digitale, usate il vostro percorso al posto di ~ nei comandi qui sopra. La cartella dei .deb già pubblicati (~/professore-digitale-archivio) resta dov'è: non va toccata.

Facoltativo, per sviluppare in futuro anche la versione Windows su questo PC: tools/prepara-ambiente.sh (installa mingw-w64, NSIS e Wine). Per pubblicare non serve.

4 · Pubblicare con un solo comando (GitHub)

4a · Prima la prova (non carica nulla)

cd ~/professore-digitale
tools/pubblica-tutto.sh ~/Scaricati/professore-digitale-2.3.0-da-pubblicare.zip --prova

Controlla le impronte di tutti i file, firma il repository APT se sul computer c'è la vostra chiave, ed elenca cosa verrebbe caricato. Deve finire con ✔ Prova completata: nessun file caricato. Nell'elenco devono comparire anche ProfessoreDigitale-Setup-2.3.0.exe, professore-digitale-windows-2.3.0.zip e catalogo-ia.json.

4b · Poi la pubblicazione vera

tools/pubblica-tutto.sh ~/Scaricati/professore-digitale-2.3.0-da-pubblicare.zip

In ordine, il comando:

  1. verifica di nuovo le impronte;
  2. firma e rigenera il repository APT, se trova la vostra chiave (altrimenti lo dice e prosegue);
  3. carica il sito su GitHub Pages (ramo gh-pages): aggiornamenti, installatore Windows, pacchetto Linux, vademecum, contenuti e catalogo dei modelli di IA;
  4. invia i sorgenti e i tag su GitHub (ramo main, tag v2.3.0).

Deve finire con ✔ Fatto!. Se GitHub chiede nome utente e password, come password va incollato il token personale (GitHub → Settings → Developer settings → Personal access tokens), non la password del sito.

Se i sorgenti non partonoSe il sito viene caricato ma compare «Invio dei sorgenti non riuscito», ripetete solo quella parte: 
cd ~/professore-digitale
git push https://github.com/danilodauria/professore-digitale.git main --tags

5 · Controllare che gli aggiornamenti arrivino

  1. Aspettate 1–2 minuti (GitHub Pages ha bisogno di un attimo).
  2. Aprite nel browser https://danilodauria.github.io/professore-digitale/aggiornamenti.json: deve comparire "versione": "2.3.0" e una sezione "windows".
  3. Su un PC con la 2.2.0: Professore Digitale → Impostazioni → Aggiornamenti → 🌐 Controlla aggiornamenti. Deve annunciare la 2.3.0 con le note; ⬇️ Scarica il nuovo pacchetto e poi sudo apt install del file scaricato (il comando esatto lo mostra il Professore).
  4. Su un PC Windows potete installare direttamente ProfessoreDigitale-Setup-2.3.0.exe. Dalle versioni successive alla 2.3.0, anche Windows si aggiornerà da Impostazioni → Aggiornamenti con il pulsante ▶ Installa adesso.

6 · In alternativa: tutto in locale, senza GitHub

Per le aule senza Internet, o se preferite non usare GitHub. LINUX

Con una chiavetta

cd ~/professore-digitale
tools/pubblica-locale.sh ~/Scaricati/professore-digitale-2.3.0-da-pubblicare.zip \
    --cartella /media/$USER/CHIAVETTA/professore-digitale

Sulla chiavetta trovate le istruzioni in LEGGIMI.txt: sui PC Linux sh installa-da-chiavetta.sh, sui PC Windows doppio clic su ProfessoreDigitale-Setup-2.3.0.exe.

Con un PC dell'aula che fa da «server degli aggiornamenti»

# sul PC server (sostituite l'indirizzo con quello vero del PC)
tools/pubblica-locale.sh ~/Scaricati/professore-digitale-2.3.0-da-pubblicare.zip \
    --cartella ~/aggiornamenti-professore --indirizzo http://192.168.1.10:8080
tools/server-aggiornamenti.sh ~/aggiornamenti-professore --servizio

Sugli altri PC: Impostazioni → Aggiornamenti, indirizzo http://192.168.1.10:8080/aggiornamenti.json, poi Controlla aggiornamenti. Copia di sicurezza senza GitHub: tools/backup-locale.sh /media/$USER/CHIAVETTA.
